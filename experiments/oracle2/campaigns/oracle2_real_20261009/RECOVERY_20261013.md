# Missing-response generation recovery

## Scope and status

This is a technical recovery of timed-out generation tasks4794738_0/1, not
new training, a new seed, or a changed evaluation protocol. Their original
source23401de and all complete/partial results remain immutable. Six training
arms are already complete. WR is still a separate, unsubmitted batch phase.

The recovery implementation is CPU-tested locally. Server validation and the
actual frozen source/deployment are recorded separately under `records/attempt5`
when completed. This document alone is not a GPU submission receipt or a GPU
inference validation. Tasks4794738_2..5 must finish successfully, and the full
owner/UID account must be empty, before recovery can be submitted.

## What is reused

Each failed arm has eight complete800-response banks, states0,10,...,70.
At the timeout snapshot, state80 has728 complete rows for IPO ordinary and561
for IPO reference. Recovery reuses these rows, leaving1672 and1839 missing
responses respectively across states80,90,100. The actual counts are checked
against frozen files again; these are not forecasts for running arms.

`generation_recovery.json` binds the original plan, audit, model lock,
evaluation support, immutable deployment and generation receipt. It also
binds each training manifest, every adapter/config file, original generation
manifest, and complete/partial bank by SHA256. Slurm must identify each
predecessor as TIMEOUT; stale RUNNING disk manifests and exit0:0 are not success.

All responses must form the exact expected prompt/draw prefix with matching
run, step, prompt key/ID/text/group, deterministic seed, and finite diagnostics.
A malformed newline-terminated row is rejected. A nonterminated final fragment
is kept in the original file, recorded by byte count/hash, and omitted only
from the new copy, since it is not a committed response.

## What changes operationally

The generator writes to a **new output tree**, never the original directory.
Complete banks are copied byte-for-byte without loading a model. Partial banks
copy only the validated prefix. The original generator's model loading,
BF16/SDPA attention, prompt encoding, adapter, sampling settings, and per-response
seed rule are retained; only missing draws are generated. Sampling is still
temperature.8, top-p.95, maximum256 new tokens. No truncation, batching,
quantization, scoring-temperature, mixture or scientific setting is changed.

Seeds are independently reset for every `(checkpoint,prompt,draw)`, so skipping
earlier draws does not consume a shared RNG stream differently. CPU mock tests
verify exact missing-draw selection and seed calls; this does not claim a new
real-GPU bitwise-reproducibility test or that recovery has already run.

`queue.py --phase recover` uses one H100/task, at most two simultaneous tasks,
with24-hour limits. It preserves exclusive intent/receipt creation, source and
review checks, full-account queue checks, and the four-GPU ceiling. It refuses
existing recovery outputs and any incomplete/failed other generation arms.
A recovery launch cannot run audit, baseline, training, or the old six-arm
generation phase. If recovery itself fails, retain the new partial output and
review it; do not repeatedly restart it blindly.

## WR routing and gates

After successful recovery, `evaluate_wr.py collect --recovery <contract>` uses
the two recovered banks and the four unchanged original arms. It verifies
every preserved prefix, adapter binding, all eleven checkpoint files and all
800 responses per file before collecting anything. The frozen original plan
and initial-policy baseline are unchanged. No partial WR curve, missing-point
interpolation, zero-filled subgroup, or fixed-panel surrogate is introduced.

WR submission still requires successful scheduler completion of the recovery
and other generators, all66 complete count/hash-valid banks, the baseline,
and an idle full account. Judges are sequential in a two-GPU job. The response
records remain private; share only aggregate/numeric reports and figures.

## Validation and deployment

Run the Oracle2 and cyclic-history CPU test suites and `bash -n run_phase.sh`.
The end-to-end mock test starts with a full bank, a partial bank including an
interrupted final fragment, and a missing bank. It checks missing-only generation,
unchanged source bytes, fixed seeds, count/hash validation, and WR collection.
Other tests reject changed adapters, settings, seeds, response order, malformed
or nonfinite records, terminal-success confusion, and occupied accounts.

`deploy_recovery.py` extracts committed code into a fresh launch, verifies
byte-identical plan/lock/review, captures and checks real frozen response
prefixes, runs server CPU tests without skips, and records a new deployment.
It never calls sbatch or creates generated response outputs. Consult the
recorded deployment and all intents/receipts before any later resource action.
